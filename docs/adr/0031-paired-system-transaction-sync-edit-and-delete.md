# 0031. 成對系統交易（轉帳／提款／報銷／還款）雙向綁定、連動編刪與資料自癒 (Paired System Transaction Sync, Edit & Delete)

## Status
Accepted

## Context
在既有系統設計中，系統內部成對產生之四類資金移轉與平帳流水：
1. **公帳代墊報銷**（共同基金撥出 `expense`，成員私帳收訖 `income`，並綁定代墊明細之 `reimbursement_id`）
2. **內部轉帳**（轉出帳戶 `expense`，轉入帳戶 `income`）
3. **ATM 提款**（銀行帳戶 `expense`，現金錢包 `income`）
4. **信用卡還款**（扣款銀行 `expense`，信用卡端 `income`，並具備 `unbilled_offset` 紀錄）

過去此四類紀錄在前端收支明細（`Transactions.tsx`）與後端（`transactions.ts`）被標記為「系統保護（唯讀）」，禁止直接修改或刪除。然而使用者在日常記帳時若金額、日期打錯或欲作廢整筆撥款，因無法編輯或刪除造成強烈痛點。若僅開放單邊編輯，勢必導致轉出／轉入雙邊帳戶餘額失衡與資料孤島。

## Decision
經由完整設計樹訪談，正式確立以下成對系統交易之生命週期、雙邊連動與防呆架構：

1. **資料庫層級成對雙向綁定 (`pair_tx_id`)**：
   - 在 `transactions` 資料表新增 `pair_tx_id TEXT` 欄位。
   - 新建 `公帳代墊報銷`、`內部轉帳`、`ATM提款`、`信用卡還款` 時，轉出端與轉入端互相記錄對方的交易 ID。
   - 針對歷史無 `pair_tx_id` 之既有紀錄，執行一次性資料庫自動補配對（依同戶、同日、同分類、同金額、一收一支、建立時間相差 10 秒內之唯一配對）；若無法唯一匹配則維持「系統保護」唯讀狀態，杜絕誤改。

2. **可編輯欄位嚴格限縮（金額、日期、備註）**：
   - 僅開放修改「金額 (`amount`)」、「日期 (`date`)」、「備註 (`note`)」，編輯任一端時，同一資料庫事務中自動同步更新對應另一端之金額與日期，並依金額差額（`newAmount - oldAmount`）即時校正雙邊帳戶餘額。
   - 轉出與轉入帳戶不開放更換。若帳戶選錯，一律要求刪除後重新操作，防止越權動支共同基金或跨成員錯帳。

3. **雙邊連動刪除與代墊自動退回**：
   - 刪除任一端流水時，系統自動成對刪除轉出與轉入兩筆紀錄，並完整回滾雙邊帳戶餘額。
   - 若刪除之紀錄為 `公帳代墊報銷`，自動將該報銷單所結清之所有代墊消費明細的 `reimbursement_id` 重置為 `NULL`，即刻安全退回「待報銷明細」清單。

4. **信用卡還款金額重新分配與重算**：
   - 修改 `信用卡還款` 金額時，依既有還款規則重新分配：優先折抵「已出帳待繳款」，超過部分轉列為「未出帳折抵 (`unbilled_offset`)」，並以實際刷卡明細冪等重算信用卡之已出帳與未出帳金額。

5. **異動權限與操作入口**：
   - **操作入口**：於「收支明細 (`Transactions.tsx`)」與「家庭協同 > 報銷紀錄 (`Family.tsx`)」同步開放編輯與刪除。
   - **權限控制**：
     - `公帳代墊報銷`：限家庭管理員或被報銷成員本人操作（與「解除報銷」權限一致）。
     - `內部轉帳` / `ATM提款` / `信用卡還款`：限當初操作者本人或家庭管理員操作。

6. **報銷金額與已結清代墊之一致性防線**：
   - 報銷金額改大時，多出的部分沿用「家庭基金溢撥／預收款」顯示。
   - 報銷金額改小至低於目前已勾選結清之代墊明細合計時，後端阻擋並提示先至「已結清明細」解除部分項目報銷。

## Consequences
- 解除長久以來的唯讀鎖定，使用者可輕鬆修正轉帳、提款、報銷與還款之金額與備註。
- 雙邊帳戶餘額與流水永遠維持 100% 數學平衡，徹底杜絕單邊改帳造成的對帳災難。
- 報銷刪除與代墊退回無縫銜接，提供完整的操作容錯性與可逆性。
