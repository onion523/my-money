# 0030. 信用卡出帳結算區間推算規則、重複出帳覆蓋機制與結帳日設定強制性 (Credit Card Statement Cycle Interval, Rollover Overwrite Semantics, and Mandatory Statement Day)

## Status
Accepted

## Context
在先前的出帳設計（ADR-0024、ADR-0028）中，信用卡「出帳作業」推算結算區間與撈取交易時存在以下不符使用者直覺與記帳習慣的問題：
1. **未到結帳日時的結算區間起日落差**：
   在當期結帳日尚未到達時（例如今日 10/17，結帳日 25 號），先前系統推算的區間是 `9/26 ～ 10/25` 或 `9/26 ～ 今日`，忽略了上期帳單（9/25 結帳）可能仍有待覆核、或使用者欲連同上期與當期累積至今的消費一起檢視核對的需求。持卡人期望當結帳日未到時，起日應精確落在「上上期結帳日隔天（8/26）」，完整涵蓋至當日（今日 10/17）。
2. **已過結帳日時的結算截止點**：
   當結帳日已經到達或過了（例如今日 10/17，結帳日 15 號），原先邏輯將截止日固定在「本期結帳日（10/15）」，導致結帳日過後到今天所發生的最新消費無法一併列入即時出帳結轉。持卡人期望起日為「上期結帳日隔天（9/16）」，截止日同樣彈性延伸到「今日（10/17）」。
3. **出帳紀錄判斷與重複出帳覆蓋**：
   原先邏輯依賴 `last_rollover_at` 判定是否推向下個月週期，導致使用者在出帳過一次後再次打開彈窗時，週期自動被推到下個月，無法重複針對當期進行覆核與覆蓋更新。持卡人期望每次打開出帳彈窗都依固定客觀日曆天推算，不依賴歷史出帳時間戳記推進月份，並允許隨時重新執行出帳作業，全面覆蓋前一次結果。
4. **未設定結帳日之卡片邊界**：
   過去未設定結帳日之卡片可盲目出帳，導致無明確週期對帳依據。應強制要求卡片必須設定每月結帳日方可進行出帳。

## Decision
經由詳細訪談與需求對齊，確立以下信用卡出帳結算區間與狀態覆蓋架構：

1. **依結帳日相對位置推算結算區間（Cycle Interval by Statement Day Position）**：
   - **情境一：當期結帳日尚未到達（`currDay < statementDay`）**：
     - **起始日**：**上上期結帳日隔天（$S_{\text{prev2}} + 1$）**。
       - 例如：今日 10/17，結帳日為 25 號：上期為 9/25，上上期為 8/25，起始日即為 **`2026-08-26`**。
     - **截止日**：**今日（當日，`taipeiDateStr`）**。
     - **彈窗頂部說明**：標示為 `「上上期次日 YYYY-MM-DD ～ 今日 YYYY-MM-DD（結帳日 N 號未到）」`。
   - **情境二：當期結帳日已達或已過（`currDay >= statementDay`）**：
     - **起始日**：**上期結帳日隔天（$S_{\text{prev1}} + 1$）**。
       - 例如：今日 10/17，結帳日為 15 號：上期為 9/15，起始日即為 **`2026-09-16`**。
     - **截止日**：**今日（當日，`taipeiDateStr`）**，包含結帳日後至今日的所有消費。
     - **彈窗頂部說明**：標示為 `「上期次日 YYYY-MM-DD ～ 今日 YYYY-MM-DD（結帳日 N 號已過）」`。

2. **歷史未結交易一併喚醒納入結算（Historical Unbilled Transactions Inclusion）**：
   - 撈取清單時，除了落入「起始日 ～ 今日」範圍內的所有交易外，**早於起始日但仍未出帳（`date <= 起始日 且 is_billed = 0`）之歷史延入款亦一併全數納入**。
   - 清單中醒目標示 `[上期延入]` 徽章，預設納入結算，確保無任何歷史遺漏漏記之消費被排擠。

3. **重複出帳覆蓋機制與預設狀態（Repeat Rollover & State Overwrite）**：
   - **純粹客觀推算，不依賴歷史出帳紀錄推進月份**：每次開啟出帳彈窗，皆依據上述兩大客觀規則推算起訖區間，不因先前已有點擊出帳而鎖死或跳月。
   - **彈窗開啟時之延期勾選狀態**：維持資料庫當前真實標記——
     - 若過去有項目被標記為延至下期（`defer_to_next_statement = 1`），打開彈窗時維持勾選延期（劃線排除於當次出帳金額）；
     - 其餘項目（包含先前已出帳 `is_billed = 1` 或新發生的 `is_billed = 0`）一律預設為納入本次出帳（未延期）。
     - 使用者可隨時手動重新勾選／取消勾選延期項目。
   - **全面覆蓋更新**：按下「確認出帳」時，本次清單中所有未延期項目全面更新為 `defer_to_next_statement = 0, is_billed = 1`；所有指定延期項目全面更新為 `defer_to_next_statement = 1, is_billed = 0`；並重新執行真實明細全量冪等重算（`recalculateCardBalances`），覆蓋前次結果。

4. **未設定結帳日卡片之強制約束（Mandatory Statement Day Policy）**：
   - 若卡片之 `statement_day` 為空（`null` 或未設定）：
     - 系統在前端出帳按鈕或點擊後即刻阻擋，明確提示：「請先至帳戶設定填寫每月結帳日，方可執行出帳作業」。
     - 後端 `GET /accounts/:id/rollover-preview` 與 `POST /accounts/:id/rollover-statement` 若遇未設定結帳日之卡片，直接回傳 HTTP 400 錯誤。

## Consequences
- 結算區間規則完全符合持卡人在結帳日前後對帳、查核上期與當期消費之實際使用心理。
- 消除「出帳過一次後想再次修改卻被迫跳到下個月」之僵化缺陷，實現隨時可重算、可覆蓋之靈活出帳作業。
- 強化未設定結帳日卡片防呆，確保所有信用卡出帳均具備健全合法的週期基準。
