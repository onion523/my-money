# 0030. 信用卡出帳結算區間推算規則、重複出帳覆蓋機制與結帳日設定強制性 (Credit Card Statement Cycle Interval, Rollover Overwrite Semantics, and Mandatory Statement Day)

## Status
Accepted

## Context
在先前的出帳設計（ADR-0024、ADR-0028）中，信用卡「出帳作業」推算結算區間與撈取交易時存在以下不符使用者直覺與記帳習慣的問題：
1. **未到當月結帳日時的結算區間偏移**：
   在當月結帳日尚未到達時（例如今日 10/17，結帳日 25 號），當月帳單根本尚未結帳，持卡人此時進行出帳作業所核對的應是「最近一期已結帳的完整對帳單」，即 **`2026-08-26 ～ 2026-09-25`**（上上期結帳日隔天 ～ 上期結帳日）。先前系統卻跳至 `9/26 ～ 10/25` 或算到今日，導致無法對齊真實銀行對帳單區間。
2. **已達或已過當月結帳日時的結算區間**：
   當當月結帳日已經到達或過了（例如今日 10/17，結帳日 15 號），10/15 帳單已結帳，此時最近一期已結帳的完整對帳單即為 **`2026-09-16 ～ 2026-10-15`**（上期結帳日隔天 ～ 本月結帳日）。
3. **出帳紀錄判斷與重複出帳覆蓋**：
   原先邏輯依賴 `last_rollover_at` 判定是否推向下個月週期，導致使用者在出帳過一次後再次打開彈窗時，週期自動被推到下個月，無法重複針對該期帳單進行覆核與覆蓋更新。持卡人期望每次打開出帳彈窗都依固定客觀日曆天推算最近一期已結帳區間，不依賴歷史出帳時間戳記推進月份，並允許隨時重新執行出帳作業，全面覆蓋前一次結果。
4. **上期延入款預設狀態與未設定結帳日之邊界**：
   標示為「上期延入」之歷史未結項目，打開出帳預覽時應一律預設列入計算（取消勾選延至下期）；且未設定結帳日之卡片應強制要求先設定結帳日方可出帳。

## Decision
經由詳細訪談與需求對齊，確立以下信用卡出帳結算區間與狀態覆蓋架構：

1. **依當月結帳日相對位置推算「最近一期完整對帳單區間」（Cycle Interval by Statement Day Position）**：
   - **情境一：當月結帳日尚未到達（`currDay < statementDay`）**：
     - **起始日（`startDate`）**：**上上期結帳日隔天（$S_{\text{prev2}} + 1$）**。
     - **結束日（`endDate` / `statementDate`）**：**上期結帳日（$S_{\text{prev1}}$）**。
       - 例如：今日 10/17，結帳日為 25 號：上上期結帳日為 8/25、上期結帳日為 9/25，結算區間為 **`2026-08-26 ～ 2026-09-25`**。
     - **彈窗頂部說明**：標示為 `「YYYY-MM-DD ～ YYYY-MM-DD（當月 N 號結帳日未到，結算上期帳單）」`。
   - **情境二：當月結帳日已達或已過（`currDay >= statementDay`）**：
     - **起始日（`startDate`）**：**上期結帳日隔天（$S_{\text{prev1}} + 1$）**。
     - **結束日（`endDate` / `statementDate`）**：**本月結帳日（$S_{\text{curr}}$）**。
       - 例如：今日 10/17，結帳日為 15 號：上期結帳日為 9/15、本月結帳日為 10/15，結算區間為 **`2026-09-16 ～ 2026-10-15`**。
     - **彈窗頂部說明**：標示為 `「YYYY-MM-DD ～ YYYY-MM-DD（當月 N 號結帳日已過，結算本期帳單）」`（若當日即結帳日則顯示 `今日為 N 號結帳日，結算本期帳單`）。

2. **歷史未結交易（上期延入款）一併喚醒且預設列入結算（Prior-Deferred Auto-Inclusion）**：
   - 撈取清單時，除了落入「起始日 ～ 今日」範圍內的所有交易外，**早於起始日（即 `date <= prevStatementDate`）但仍未出帳（`is_billed = 0`）之歷史延入款亦一併全數納入**，並標記為 `is_prior_deferred = true`（清單醒目標示 `[上期延入]` 徽章）。
   - **上期延入預設取消延期、直接列入計算**：凡屬 `[上期延入]`（`is_prior_deferred = true`）之項目，即使先前在資料庫中帶有 `defer_to_next_statement = 1`，於開啟出帳預覽彈窗時**一律預設取消勾選「延至下期」（`is_initially_deferred = false`），預設直接列入本期出帳淨額計算（不劃線）**；若持卡人欲再度順延，可當場手動點擊「延至下期」。

3. **重複出帳覆蓋機制與當期延期狀態保持（Repeat Rollover & State Overwrite）**：
   - **純粹客觀推算，不依賴歷史出帳紀錄推進月份**：每次開啟出帳彈窗，皆依據上述兩大客觀規則推算起訖區間，不因先前已有點擊出帳而鎖死或跳月。
   - **彈窗開啟時之延期勾選狀態分流**：
     - **上期延入項目（`is_prior_deferred = true`）**：一律預設取消勾選延至下期（`is_initially_deferred = false`），列入本期出帳計算。
     - **本期區間內項目（`is_prior_deferred = false`）**：若在當期被標記為延至下期（`defer_to_next_statement = 1 且 is_billed = 0`），打開彈窗時維持勾選延期（`is_initially_deferred = true`，劃線排除於當次出帳金額）；其餘項目（包含先前已出帳 `is_billed = 1` 或新發生的 `is_billed = 0`）一律預設為納入本次出帳（`is_initially_deferred = false`）。
     - 使用者可隨時手動重新勾選／取消勾選任何項目的延期狀態。
   - **全面覆蓋更新**：按下「確認出帳」時，本次清單中所有未延期項目全面更新為 `defer_to_next_statement = 0, is_billed = 1`；所有指定延期項目全面更新為 `defer_to_next_statement = 1, is_billed = 0`；並重新執行真實明細全量冪等重算（`recalculateCardBalances`），覆蓋前次結果。

4. **未設定結帳日卡片之強制約束（Mandatory Statement Day Policy）**：
   - 若卡片之 `statement_day` 為空（`null` 或未設定）：
     - 系統在前端出帳按鈕或點擊後即刻阻擋，明確提示：「請先至帳戶設定填寫每月結帳日，方可執行出帳作業」。
     - 後端 `GET /accounts/:id/rollover-preview` 與 `POST /accounts/:id/rollover-statement` 若遇未設定結帳日之卡片，直接回傳 HTTP 400 錯誤。

## Consequences
- 結算區間規則完全符合持卡人在結帳日前後對帳、查核上期與當期消費之實際使用心理。
- 消除「出帳過一次後想再次修改卻被迫跳到下個月」之僵化缺陷，實現隨時可重算、可覆蓋之靈活出帳作業。
- 強化未設定結帳日卡片防呆，確保所有信用卡出帳均具備健全合法的週期基準。
