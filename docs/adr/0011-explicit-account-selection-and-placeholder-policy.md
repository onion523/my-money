# 0011. 全站顯式帳戶選取規範與佔位防呆政策 (Explicit Account Selection and Placeholder Policy)

## Status
Accepted

## Context
在個人與家庭雙帳本系統中，資金會計實體（現金錢包、銀行存款帳戶、信用卡帳戶）的精確性直接決定資產負債與各成員代墊款的正確性。然而過去在前端多個表單中存在以下隱性預選（Implicit Default）問題：
1. **記帳表單隱性預設首項**：在快速記帳（Dashboard）與交易明細（Transactions）的新增彈窗中，若表單尚未指定帳戶，程式會自動預設選取帳戶列表的第一個項目（`accounts[0]`），且下拉選單中無空白佔位項目。使用者若未刻意檢查下拉選單便點擊儲存，極易將應記在信用卡或另一銀行的消費誤記到第一筆帳戶（通常是現金或主要活存），造成帳目錯亂與手動核帳困擾。
2. **週期收支表單自動綁定**：在週期收支新增彈窗中，同樣自動預設帶入 `accounts[0]`，而非符合領域模型設定的「無特定帳戶」。
3. **轉帳與結算表單自作主張**：在帳戶轉帳（Accounts）、信用卡扣款還款（Accounts）與家庭公帳代墊報銷（Family）等專項作業中，開窗時皆有自動尋找第一筆銀行、現金或公帳的自動代入邏輯，可能導致使用者未察覺已預選的目標帳戶而送出非預期的資金移轉。

## Decision

經過訪談對齊（`grill-with-docs`），確立「**全站顯式帳戶選取（Explicit Account Selection）**」與嚴格防呆政策：

### 1. 全站表單全面取消帳戶隱性預選 (Zero Default Policy)
- **新增交易記帳**（Dashboard 快速記帳、Transactions 頁面「+ 記一筆」）：
  - 表單狀態初始為 `account_id: ''`，徹底移除 `useEffect` 中自動鎖定 `accounts[0]` 的邏輯。
  - 下拉選單開頭加入 `-- 請選擇扣款 / 存入帳戶 --` 佔位符。
- **新增週期收支**（Recurring 頁面「+ 新增週期收支」）：
  - 初始 `account_id: ''`，開窗時不帶入任何帳戶。
- **帳戶內部轉帳**（Accounts 頁面轉帳彈窗）：
  - 頂部全域入口（「帳戶轉帳 / ATM提款」按鈕）開啟時，轉出與轉入帳戶雙邊皆為空值（`from_account_id: ''`, `to_account_id: ''`）。
- **信用卡扣款還款**（Accounts 頁面）：
  - 點擊還款開啟彈窗時，扣款銀行欄位預設為空值（`bank_account_id: ''`），不自動鎖定餘額大於零之銀行。
- **家庭公帳代墊報銷**（Family 頁面）：
  - 開啟報銷彈窗時，撥款公帳與入帳個人帳戶雙邊皆為空值（`from_account_id: ''`, `to_account_id: ''`），不自動預填。
- **編輯現有資料之例外維持**：
  - 當使用者點開「編輯現有交易」或「編輯現有週期收支」時，如實載入該筆記錄原本已儲存的帳戶，不予清空。

### 2. 佔位選項屬性分級（必填 disabled vs 選填可反選）
- **必填欄位 (Required Account Fields)**：
  - 涵蓋：交易記帳、帳戶互轉、信用卡還款、代墊款報銷。
  - 佔位項目統一加上 `disabled` 屬性，例如：`<option value="" disabled>-- 請選擇扣款 / 存入帳戶 --</option>`。
  - **行為**：開窗時預設選取該提示項；一旦使用者點選了任一有效帳戶後，不能再把選單切回空值，杜絕必填表單中選回無效狀態的困擾。若未選即送出，由 HTML5 `required` 與表單紅字警示雙重攔截。
- **選填欄位 (Optional Account Fields)**：
  - 涵蓋：週期收支（Recurring Items）的關聯帳戶。
  - 佔位項目**不加 `disabled`**，文案維持 `<option value="">無特定帳戶</option>`。
  - **行為**：開窗初始停在「無特定帳戶」；使用者隨時可以選取特定帳戶，亦可隨時切回「無特定帳戶」，送出時允許為空。

### 3. 單卡脈絡入口與快捷按鈕處理
- **單卡脈絡操作**：
  - 在指定銀行卡片點擊「轉出」：轉出帳戶帶入該指定銀行（符合使用者點該卡的脈絡），但轉入帳戶保持為空（`-- 請選擇轉入帳戶 --`）。
  - 在指定現金卡片點擊「ATM 提領現鈔至此」：轉入帳戶帶入該現金錢包，但轉出帳戶保持為空（`-- 請選擇轉出帳戶 --`）。
- **彈窗內快捷填寫按鈕**：
  - 轉帳彈窗內的「🏧 ATM 提領現鈔」與「🏦 存入現金至銀行」快捷按鈕完整保留，視為使用者主動發起的填入輔助，非被動預選。

## Consequences
- **優點**：
  1. 徹底根除使用者「未注意下拉已預填而誤記、誤轉、誤繳」的高風險人為失誤。
  2. 必填帳戶表單透過 disabled 佔位符與即時驗證，保障資料輸入嚴謹度。
  3. 保留週期收支選填靈活性，並兼顧單卡脈絡操作的流暢性。
- **缺點與因應**：
  - 使用者每次新增交易或發起轉帳時需多點擊一次下拉選取帳戶；但相比記錯帳戶導致回滾與重複修補的時間成本，顯式選取能大幅提高記帳可靠性。
