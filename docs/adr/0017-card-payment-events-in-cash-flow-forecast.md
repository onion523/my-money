# 17. 現金流預測納入信用卡繳款日事件 (Card Payment Events in Cash Flow Forecast)

Date: 2026-10-03

## Status

Accepted

## Context

現金流預測（ADR 0016）的第 0 天起始餘額，已一次扣除全部信用卡欠款（已出帳 + 未出帳）。因此時間軸上看不到「哪一天繳卡費、錢少了多少」，折線圖低估了繳款日前的餘額、高估了繳款日後的下滑時點。

週期收支綁定信用卡時，預測只用於參考；實際刷卡與繳款，使用者仍會手動記帳。預測只涵蓋未來 30 天，已過的扣款日本來就不會出現，因此不需要「標記已入信用卡帳」按鈕（已討論並捨棄）。

## Decision

1. **繳卡費事件**：在預測時間軸上，於各信用卡的下一個繳款日 (`payment_due_day`)，產生一筆「💳 繳卡費」支出事件，金額為該卡「已出帳餘額 (Billed Debt)」。
2. **起始餘額改為只扣未出帳**：第 0 天起始餘額不再扣已出帳欠款，改於繳款日事件扣除；未出帳 (Unbilled Debt) 仍於起始餘額預先扣除（保守，避免重複計算也避免低估）。
3. **退回起始扣除的條件**：該卡未設定繳款日，或下一個繳款日不在預測窗口內時，已出帳欠款維持在第 0 天一次扣除，不產生事件。
4. **三態視角拆分**：
   - 🏠 公帳：共同卡全額 + 私卡的「公帳代墊部分」。
   - 🔒 私帳：自己私卡的「個人部分」。
   - 🌐 全部：兩者加總（他人私卡僅計公帳代墊部分，隱私遮蔽）。
   - 私卡公私拆分沿用帳戶管理既有 `shared_debt` / `personal_debt` 比例，套用於已出帳餘額。
5. **週期收支綁卡**：週期收支維持於其扣款日依現行規則進入預測，僅在排程卡片額外標示綁定帳戶；不新增手動標記按鈕，亦不自動建立交易。

## Consequences

- 折線圖能真實反映繳卡費當天的現金下滑；`minBalance` 與透支風險判定更貼近實際。
- 起始餘額語意與 ADR 0015 的「帳戶管理淨可用餘額」在預測頁不再完全相同（預測頁已出帳部分延後到繳款日扣）。
- 既有 `getForecastStartingBalance` 與 `purchase-check` 需同步調整。
