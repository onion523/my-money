# 18. 現金流預測單筆事件勾選已繳豁免機制 (Forecast Event Settlement & Double-Counting Exemption)

Date: 2026-10-03

## Status

Accepted (Supersedes the "no mark button" clause of ADR 0017)

## Context

在「現金流預測（`Forecast.tsx`）」中，系統會模擬未來 30 天的所有週期收支排程與信用卡繳款日事件（ADR 0016, ADR 0017）。然而在真實日常記帳場景中，經常發生以下「重複計算（Double-Counting）」問題：

1. **提早刷卡／入信用卡未出帳或提前繳納**：
   - 例如某筆週期支出（如水電費、保險費或訂閱費）預計在 15 號扣款，但使用者在 10 號就已經刷卡或轉帳並手動記了一筆帳。
   - 此時該筆實際消費已經反映在「銀行存款餘額減少」或「信用卡未出帳負債（`unbilled`）增加」中（已在第 0 天起始餘額扣除）；但未來 30 天預測排程在 15 號仍會再扣一次該筆週期支出，導致現金流被重複扣除兩次。
2. **信用卡帳單提早繳清或部分處理**：
   - 當期「💳 繳卡費」事件或週期收入已提前入帳時，若無法針對單一筆排程事件標記「已繳／已入帳」，預測折線圖與最低餘額（`minBalance`）將失真。

## Decision

我們決定在現金流預測模組導入**「單筆預測事件勾選已繳豁免機制（Forecast Event Settlement Exemption）」**：

### 1. 適用範圍與唯一識別碼 (`event_key`)
- **全事件支援勾選**：未來 30 天排程中的所有事件——包含「週期支出」、「週期收入」以及「💳 繳卡費」事件，皆可針對單一筆排程進行勾選或取消勾選。
- **當期事件唯一識別碼 (`event_key`)**：
  - 週期收支事件：`recurring:<recurring_id>:<YYYY-MM-DD>`
  - 信用卡繳卡費事件：`card_due:<account_id>:<YYYY-MM-DD>`
  - 綁定特定預計發生日期 `YYYY-MM-DD`，確保勾選「已繳」僅豁免**當期這一次**排程，下個週期的排程自動維持未繳狀態。

### 2. 現金流與購買力計算豁免規則
- 當某筆預測事件被標記為 `is_settled = true`（已繳）時：
  1. **不列入現金流計算**：在 `GET /api/forecast` 的 30 天逐日餘額模擬（`dailyBalances`）、最低餘額點（`minBalance`）與透支風險（`willOverdraft`）計算中，該筆事件金額視為 `0`（不重複加減）。
  2. **不列入購買力試算**：在 `POST /api/forecast/purchase-check` 中，同樣跳過已勾選 `is_settled = true` 的事件，確保購買力評估精準反映最新可用資金。

### 3. 前端排程清單呈現與可逆操作
- **保留於排程清單並視覺降噪**：已勾選事件不從「未來 30 天收支排程」清單消失，而是呈現為**半透明樣式、金額加上刪除線，並標示「✅ 已繳（不計入預測）」徽章**。
- **一鍵切換（Toggle）**：每張排程卡片提供勾選按鈕，點擊即可切換「已繳 ↔ 未繳」，並即時重新計算折線圖與安全評級。

### 4. 後端持久化與 ADR 0013 權限防線
- **資料表 `forecast_settled_events`**：於 D1 資料庫建立 `forecast_settled_events (event_key TEXT PRIMARY KEY, household_id TEXT, user_id TEXT, settled_by TEXT, created_at DATETIME)`（支援自動平滑遷移）。
- **跨裝置與家庭共治同步**：
  - **🔒 私帳事件 (`is_shared = 0`)**：僅限該項目建立者／持卡人本人可勾選或取消勾選，非本人操作回傳 `403 Forbidden`。
  - **🏠 公帳事件 (`is_shared = 1`)**：對齊 ADR 0013 共治原則，限「該項目建立者／持卡人本人」或「家庭管理員 (`admin`)」可勾選與取消勾選；一旦勾選，全體家庭成員檢視公帳或全部視角時，皆同步看到「✅ 已繳」且不再重複扣款。

## Consequences

- **徹底消除重複扣款失真**：無論是信用卡提前入帳、帳單提前繳納或薪資提前入帳，勾選後即刻從預測扣除中豁免，折線圖與最低餘額 100% 貼合真實財務狀況。
- **跨期零維護成本**：因 `event_key` 綁定單次預計日期 `YYYY-MM-DD`，使用者無須在下個月手動重置勾選狀態。
