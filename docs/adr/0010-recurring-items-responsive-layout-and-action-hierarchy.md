# 0010. 週期收支 Mobile-First 響應式佈局、雙軌編輯刪除路徑與內建防誤觸確認 (Recurring Items Responsive Layout, Dual-Action Hierarchy, and In-App Confirmation)

## Status
Accepted

## Context
在行動裝置（iOS/Android 瀏覽器、PWA、窄螢幕 <=768px）實際操作記帳系統時，週期收支（`/recurring`）頁面存在以下核心體驗與版面問題：
1. **小螢幕嚴重擠壓跑版**：卡片採用單行水平排版（`display: flex; justify-content: space-between`），左側承載名稱、週期標籤、扣款日標籤、關聯帳戶與月分攤平滑說明，右側承載金額與圖示按鈕。在窄螢幕下無斷點換行機制，整行內容嚴重擠壓溢出，導致按鈕被擠出螢幕或跑版錯位。
2. **缺乏直觀編輯入口與流程割裂**：卡片上僅有 15px 的微小圖示，在觸控螢幕上極難點擊；且使用者點開「編輯週期收支 Modal」後，彈窗內部僅有儲存按鈕，完全缺乏「刪除」功能，導致操作流程割裂。
3. **依賴原生 `window.confirm` 導致行動端刪除失效**：刪除邏輯使用瀏覽器原生 `window.confirm`，在特定行動瀏覽器、iOS Safari、PWA 或 WebView 中極易遭到靜默阻擋或觸控焦點遺失，造成使用者「點擊刪除無反應」的假死現象。
4. **領域名詞與 CONTEXT.md 不一致**：畫面上殘留舊版名詞（如「新增固定項目」、「固定收入每月預估」、「建立固定項目」），違反 `CONTEXT.md` 規範（明確要求使用 `Recurring Item (週期收支)`，避免使用 `固定支出 (fixed expense)`）。

## Decision

經過設計樹訪談（`grill-with-docs`），確立以下規格與架構決策：

### 1. Mobile-First 垂直階層自適應卡片結構 (Responsive Card Hierarchy)
- **窄螢幕階層折疊**：當螢幕寬度 `<= 768px` 時，卡片由單行水平排列轉為清晰的垂直分層結構：
  - **第一層（標題與金額）**：項目名稱與粗體金額在左右兩側對齊呈現。
  - **第二層（週期與扣款日）**：週期標籤（如「每月繳」）與扣款日標籤（如「每月 15 號扣款」）。
  - **第三層（會計關聯與月分攤平滑）**：關聯扣款/入帳帳戶名稱，以及換算之月分攤平滑金額（`Amortization`）。
  - **第四層（操作列）**：觸控友善的「✏️ 編輯」與「🗑️ 刪除」按鈕列（觸控高度符合 `>= 36px` 規範）。
- **寬螢幕維持優雅**：寬度 `> 768px` 時維持優雅橫向排列，兼顧桌面大螢幕的高資訊密度。
- **頂部操作規範化**：頁面頂部按鈕列對齊全站規範，使用 `.page-header-row` 與 `.header-actions`，小螢幕自適應滿寬排列。

### 2. 雙操作路徑整合與點擊卡片編輯 (Dual-Action Flow & Full-Card Tap)
- **點擊卡片本體喚起編輯**：小螢幕上點擊卡片任何非按鈕區域，直接彈出「編輯週期收支」Modal，免除點擊微小按鈕的負擔。
- **獨立操作按鈕**：卡片上保留獨立的「編輯」與「刪除」按鈕，點擊時觸發 `e.stopPropagation()` 阻斷卡片點擊事件。
- **Modal 內整合刪除入口**：在「編輯週期收支」Modal 底部左下角新增「刪除此項目」紅色按鈕，讓使用者檢視或修改資料時，可一鍵直覺完成刪除。

### 3. App 內建二段式防呆確認機制 (In-App Two-Step Confirmation)
- **徹底廢除原生 `window.confirm`**：全站週期收支刪除操作全面移除原生彈窗，杜絕行動端遭瀏覽器阻擋之隱患。
- **防誤觸二次確認**：
  - 點擊刪除按鈕時，按鈕即時切換為「⚠️ 確定刪除？再次點擊確認」的高對比警戒狀態，並具備 3 秒未操作自動復原的防呆計時器；或彈出符合全站水彩磨砂玻璃質感的輕量確認對話框。
  - 再次點擊方觸發後端 `DELETE /api/recurring/:id`，防誤觸且零延遲。

### 4. 全站領域正名 (Full Terminology Alignment)
- 將前端畫面上所有舊詞彙全面對齊 `CONTEXT.md`：
  - 「新增固定項目」➔ **「新增週期項目」**
  - 「建立固定項目」➔ **「建立週期收支」**
  - 「固定收入項目」➔ **「週期收入項目」**
  - 「固定收入」➔ **「週期收入」**
  - 「週期支出每月平均分攤平滑」➔ 對齊 **`Amortization (分攤平滑)`** 概念

## Consequences
- **優點**：
  1. 徹底消滅行動端水平溢出與文字按鈕互擠的嚴重跑版問題。
  2. 提供「點卡片直接編輯」與「Modal 內隨時刪除」的最佳行動體驗。
  3. 杜絕 iOS Safari / PWA 阻擋 `window.confirm` 造成的刪除假死現象，大幅提高穩定度與防誤觸性。
  4. 領域用字與會計概念全站嚴格一致，掃除舊名詞雜訊。
- **缺點與因應**：
  - 卡片高度在小螢幕上因垂直分層會略微增加，但換來大幅提升的可讀性與觸控命中率，符合現代行動金融介面規範。
