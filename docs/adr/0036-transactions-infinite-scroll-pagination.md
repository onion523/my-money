# ADR 0036: 收支明細無限捲動分頁載入 (取代 limit=200 單次載入)

## 狀態 (Status)
已接受 (Accepted) — 2026-11-07

## 背景與問題 (Context & Problem)
`web/src/pages/Transactions.tsx` 以 `limit=200` 單次載入，後端 `GET /transactions` 亦將 `limit` 上限鎖定為 200，超過 200 筆的歷史收支無法瀏覽；且篩選與合計皆在前端對已載入資料進行，一旦分頁就會失真。

## 決策 (Decision)
1. 後端已支援 cursor 分頁 (`next_cursor`)，前端改為每頁 50 筆，由 `IntersectionObserver` 哨兵自動載入；底部顯示載入骨架、失敗重試按鈕與「已顯示全部 N 筆」結尾提示。
2. 類型／分類／帳戶／關鍵字／日期篩選全部下推後端（多欄位關鍵字 `q` 與前端既有比對範圍：備註、分類、帳戶名、記帳人對齊）。
3. 頂部合計與筆數改用 `GET /transactions/summary/range`（相同篩選條件）。
4. 新增／編輯／刪除後就地重載已載入範圍並保留捲動位置；篩選變更才重置。
5. 歷史備忘推薦維持以已載入資料建立。

## 後果 (Consequences)
- 可瀏覽全部歷史收支；合計正確且與載入頁數無關。
- 前端不得再依賴「全量資料在記憶體」之假設（日期群組需跨頁合併同一天）。
