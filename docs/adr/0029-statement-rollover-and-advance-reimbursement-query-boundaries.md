# 0029. 信用卡出帳作業與家庭代墊沖銷項目清單撈取邏輯、狀態透視與權責邊界 (Statement Rollover and Advance Reimbursement Query Boundaries, Status Transparency, and Liability Shift)

## Status
Accepted

## Context
當家庭成員使用個人私卡刷卡支付公帳（`is_shared = 1, a.is_joint = 0, account_type = 'credit_card'`）時，該筆交易在領域模型中同時承載兩種不同生命週期：
1. **信用卡結算週期（持卡人對銀行）**：未出帳（`is_billed = 0`）累積至結帳日，透過「出帳作業」結轉為已出帳待繳款（`is_billed = 1`）。
2. **家庭代墊報銷週期（成員對家庭共同基金）**：成員以個人資金墊付，透過家庭協同「報銷沖帳」由共同基金撥款至成員個人帳戶結清（填入 `reimbursement_id`）。

在此之前，系統在兩者項目清單的撈取與金額統計上存在以下邊界模糊與盲區：
1. **公帳代墊已於家庭報銷，但信用卡出帳時仍算作家庭欠款**：
   `GET /accounts/:id/rollover-preview` 在計算 `sharedDebt` 時，僅單純依 `is_shared = 1` 統計。若該筆代墊款早在結帳日前已由家庭共同基金撥款報銷給持卡人，出帳作業彈窗仍顯示「家庭代墊公帳小計 NT$ X,XXX」，造成持卡人與家庭誤以為家庭仍欠該筆卡費的嚴重認知混淆與重複討債風險。
2. **家庭協同代墊清單缺乏信用卡出帳狀態透視**：
   `GET /households/advances` 僅撈取交易之基本資訊，未回傳 `is_billed` 與 `defer_to_next_statement`。家庭成員在代墊明細與報銷彈窗中，無法得知該筆刷卡代墊究竟銀行已經出帳，抑或仍處於未出帳或延至下期狀態。
3. **退款（刷退）折抵與負數代墊規則未定義**：
   公帳退款（`type = 'income', is_shared = 1`）在信用卡出帳公私帳拆解與家庭代墊待報銷總額抵扣中的沖抵優先順序需明文化。
4. **帳戶列表卡片債務與家庭淨可用資金之連動邊界**：
   需確認帳戶列表的 `shared_debt` 是否受家庭內部報銷轉帳影響，以維持底層記帳一致性。

## Decision
經由完整設計樹訪談，正式確立以下清單撈取、狀態透視與權責邊界架構：

1. **解耦並行＋雙向狀態透視（Decoupled Parallel Lifecycle & Status Transparency）**：
   - **隨刷隨報**：家庭代墊報銷與信用卡出帳作業生命週期各自獨立並行，不強制要求代墊款必須等待信用卡出帳日後方可請款。成員只要墊款，隨時可於家庭協同申請撥款實報實銷。
   - **雙向透明透視**：信用卡出帳作業清單透視家庭報銷狀態；家庭代墊清單與報銷彈窗完整透視信用卡出帳狀態。

2. **信用卡出帳之已報銷責任轉移（Household Reimbursement Liability Shift）**：
   - 在 `GET /accounts/:id/rollover-preview` 撈取週期明細時，包含 `reimbursement_id`。
   - **清單徽章分流**：
     - 若 `is_shared = 1` 且尚未報銷（無 `reimbursement_id`）：標示 **`[公帳 · 待報銷]`** 暖橘色徽章。
     - 若 `is_shared = 1` 且已於家庭報銷結清（有 `reimbursement_id`）：標示 **`[公帳 · 家庭已報銷]`** 柔綠色徽章。
   - **公私帳拆解計算公式重構**：
     - 該筆刷卡仍計入卡片本期總出帳淨額（`netRolledAmount`），確保卡片待繳款與銀行帳單吻合。
     - 但在公私帳責任拆解中，**已報銷之公帳代墊不計入公帳欠款（`sharedDebt` 為 0）**，全額轉為持卡人個人應繳私債（`personalDebt`）。因為家庭共同基金已先行撥款將款項補償給持卡人，持卡人應自負向銀行繳款責任，徹底防範雙重計算。

3. **家庭協同代墊清單透視信用卡出帳狀態**：
   - `GET /households/advances` 補齊查詢 `t.is_billed, t.defer_to_next_statement`。
   - 在代墊明細清單與「報銷沖帳」彈窗中，凡扣款帳戶為信用卡者，依其狀態醒目標示語意徽章：
     - `defer_to_next_statement = 1`：**`[延至下期]`**
     - `is_billed = 1`：**`[已出帳]`**
     - `is_billed = 0`：**`[未出帳]`**
   - **延期項目報銷權益保障**：即使該筆刷卡在信用卡出帳時被持卡人勾選「延至下期」，家庭協同代墊清單仍正常撈取並允許勾選報銷，不因持卡人延後向銀行結帳而影響其向家庭請款之實報實銷權利。

4. **公帳退款（刷退）精準自動折抵**：
   - **信用卡出帳端**：當期之公帳刷退（`type = 'income', is_shared = 1`）優先折抵當期未報銷公帳欠款 `sharedDebt`。
   - **家庭代墊端**：公帳退款作為負數項目即時抵扣成員待報銷總額。若累計待報銷淨額小於 0，系統明確標示為「公帳待抵扣」，並停用撥款報銷按鈕，留待成員後續代墊時自動平帳沖抵。

5. **帳戶列表卡片與家庭淨可用資金獨立解耦**：
   - 帳戶列表卡片之公私帳債務矩陣（`shared_debt` 與 `personal_debt`）以及頂部淨可用資金，維持依底層交易原始之 `is_shared` 屬性計算，與家庭協同內部報銷撥款流水完全不連動，確保帳戶層面資產負債實體清晰。

6. **代墊清償雙軌並行互補**：
   - **軌道一（家庭協同報銷）**：自共同基金撥款至成員個人銀行／現金帳戶，款項結清後於信用卡出帳時轉由成員個人自負向發卡機構繳費。
   - **軌道二（帳戶列表繳家庭代墊）**：自共同基金直接還款至信用卡，直接沖減信用卡之公帳待繳債務（`billed_shared_debt`）。
   - 兩軌定位清晰獨立，滿足家庭不同財務調度習慣。

## Consequences
- 徹底消除信用卡出帳作業與家庭協同代墊報銷之間長久存在的資料孤島與邏輯斷層。
- 消除「家庭已撥款報銷，信用卡出帳卻仍顯示家庭欠款」的嚴重認知衝突與雙重請款風險。
- 代墊清單全量透視信用卡出帳狀態（未出帳／已出帳／延至下期），資訊透明度達 100%。
- 保障持卡人請款自由度，刷卡即可報銷，延至下期亦可報銷，符合真實家庭生活財務節奏。
