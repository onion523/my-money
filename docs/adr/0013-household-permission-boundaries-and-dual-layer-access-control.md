# 13. 家庭管理員與個人權限雙層防禦架構 (Household Permission Boundaries & Dual-Layer Access Control)

Date: 2026-10-01

## Status

Accepted

## Context

在《My-Money》雙帳本架構中，家庭協同記帳涉及多位成員、家庭共同基金（`is_joint = 1`）與各成員個人私密帳戶（`is_joint = 0`）。
在先前的實作中，存在以下權限邊界未清與安全漏洞：
1. **家庭組織權力未分級**：任何成員皆可呼叫 `POST /households/invite` 生成邀請碼。
2. **公帳代墊報銷無門檻**：任何成員皆可自共同基金撥款給任何人，缺乏財務管理防線。
3. **帳戶越權修改與刪除**：在 `accounts.ts` 中，只要帳戶屬於同家庭成員名下，任一成員即可修改其餘額或執行刪除，甚至波及他人私帳。
4. **交易記錄越權竄改**：在 `transactions.ts` 中，同家庭任一成員皆可修改或刪除其他成員記錄的交易（包含他人私帳流水與公帳支出）。
5. **前端 UI 與後端 API 缺乏一致的鑑權防線**：前端所有卡片無條件展示編輯與刪除按鈕，後端缺乏 403 Forbidden 檢查。

為保障成員個人財務隱私，同時兼顧家庭協同記帳的便利性與共同基金的資金安全，需要建立明確的角色權限模型與前後端雙層防禦機制。

## Decision

我們決定建立「家庭管理員（Household Admin）」與「一般家庭成員（Household Member）」之分級權限，並對「個人私帳」與「家庭公帳」實施前後端雙層防禦機制（Dual-Layer Access Control）：

### 1. 角色定義與組織治理權限 (Household Governance)
- **家庭管理員 (`admin`)**：
  - 建立家庭者自動成為管理員；若管理員退出家庭且尚有其他成員，自動轉移管理員身分。
  - **專屬權限**：僅管理員可生成家庭邀請碼（`POST /households/invite`）、移除成員（`DELETE /households/members/:targetUserId`）與解散家庭。
  - **撥款權限**：可自共同基金執行報銷撥款給家庭中任何有待報銷款項之成員。
- **一般成員 (`member`)**：
  - 透過邀請碼加入之家庭成員。
  - **受限權限**：不可生成邀請碼（後端攔截 403）、不可移除其他成員（後端攔截 403）。
  - **自律報銷權限**：僅能自共同基金為「自己的待報銷代墊款」執行撥款報銷（`target_user_id === userId`），嚴禁動支撥款給其他成員。

### 2. 資產帳戶異動權限邊界 (Account Mutation Boundary)
- **個人私帳 (`is_joint = 0`)**：
  - 具備絕對主權與最高隱私隔離。
  - 僅帳戶擁有者本人（`user_id === userId`）可查詢、修改（PUT）或刪除（DELETE）。
  - 家庭內其他成員（包含家庭管理員）皆嚴禁查詢他人私帳，且後端嚴格禁止修改或刪除非本人私帳，違者回傳 HTTP 403 Forbidden（或 404 防探測）。
- **家庭共同帳戶 (`is_joint = 1`, 共同基金 / 家庭信用卡)**：
  - 全體家庭成員皆可查詢並於記帳時選用。
  - **異動與刪除權限**：僅「該共同帳戶建立者本人」或「家庭管理員」有權編輯或刪除。一般成員若非建立者，後端攔截並回傳 403。

### 3. 交易記錄異動權限邊界 (Transaction Mutation Boundary)
- **個人私帳交易 (`is_shared = 0`)**：
  - 僅記錄者本人可見、可增、可改、可刪。
- **家庭公帳交易 (`is_shared = 1`)**：
  - 全體家庭成員皆可查詢與記帳。
  - **編輯與刪除權限（建立者與管理員共治）**：僅「該筆交易建立者本人（`t.user_id === userId`）」或「家庭管理員（`role === 'admin'`）」可執行修改（PUT）或刪除（DELETE）。一般成員若非該筆交易建立者，後端嚴格阻擋並回傳 HTTP 403 Forbidden。

### 4. 信用卡還款沖銷與結帳出帳 (Credit Card Settlement)
- **個人信用卡 (`is_joint = 0`)**：還款沖銷 (`/pay-credit-card`) 與出帳作業 (`/:id/rollover-statement`) 嚴格僅限持卡人本人操作。
- **共同信用卡 (`is_joint = 1`)**：家庭內所有成員皆可協助執行還款沖銷與出帳結算作業。

### 5. 前後端雙層防禦機制 (Dual-Layer Access Control)
- **前端視覺與防呆控制 (UI Gating)**：
  - `Family.tsx`：非管理員不顯示「邀請碼」按鈕與成員「移除」按鈕；代墊報銷僅在本人卡片顯示撥款按鈕。
  - `Accounts.tsx`：非本人且非管理員的共同帳戶卡片，自動隱藏編輯與刪除按鈕；他人私帳完全不載入。
  - `Transactions.tsx`：非本人且非管理員的公帳交易，清單項自動隱藏編輯與刪除按鈕。
- **後端 API 絕對安全屏障 (API Guard)**：
  - 所有變更與刪除端點強制檢驗 `userId`、`account.user_id`、`tx.user_id` 與 `myRole`。
  - 越權操作統一回傳 `{ success: false, error: '權限不足：[詳細原因]' }` 配合 HTTP 狀態碼 `403 Forbidden`。

## Consequences

### Positive
- **資料安全性顯著提升**：徹底消除家庭成員間誤改、誤刪他人私帳或惡意竄改公帳流水的安全隱患。
- **管理與協同平衡**：管理員擁有組織治理能力，成員享有個人私帳絕對隱私，並保留共同記帳與自律報銷彈性。
- **介面乾淨防呆**：無權限的操作按鈕在前端自適應隱藏，避免使用者遭遇無效點擊或錯誤彈窗。

### Negative / Trade-offs
- 後端在 `transactions.ts`、`accounts.ts` 與 `households.ts` 中需於每次異動前精準查詢目前使用者在家庭中之 `role`，增加少許 D1 查詢開銷（可透過既有 `getUserHousehold` 批次載入緩解）。
